# חיפוש חכם בתיבת Gmail (RAG)

המערכת עונה על שאלות בשפה חופשית על תיבת המייל, ומציגה את המיילים והקבצים המצורפים שעליהם התבססה התשובה.
למשל: "מה בעל הדירה הסכים לגבי התיקונים?", או "מתי ישיבת סיכום הרבעון?".
החיפוש המובנה של Gmail מוצא מילים. המערכת הזו עונה על שאלות, מבינה עברית ואנגלית, יודעת שמידע מתעדכן, ומוצאת גם קבצים מצורפים.

את הקוד אפשר להריץ על ייצוא אמיתי מ-Google Takeout (קובץ mbox). להגשה מצורפת **תיבת דמו בדויה** בשם `demo`: 102 מיילים של משפחה חרדית בדויה, שעוברים בדיוק באותו קוד.

## הרצה

1. **Python 3.12 ומעלה.** משתמשי נטפרי צריכים 3.12 דווקא (ראו בעיה 13 בהמשך).
2. **התקנה:**
   ```
   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```
3. **מפתח Gemini** (חינמי, מ-https://aistudio.google.com/apikey), במשתנה סביבה בלבד:
   ```
   setx GOOGLE_API_KEY <המפתח>
   ```
   אחרי `setx` צריך לפתוח טרמינל חדש.
   לתיבה אמיתית (ברירת המחדל שלה היא OpenAI) מגדירים גם `setx OPENAI_API_KEY <המפתח>`.
4. **אינדוקס תיבת הדמו:** כ-2 דקות, כי המסלול החינמי מגביל את קצב ה-embeddings.
   ```
   .venv\Scripts\python indexer.py
   ```
5. **הממשק** (או לחיצה כפולה על `הפעלה.bat`):
   ```
   .venv\Scripts\streamlit run app.py
   ```

## ארכיטקטורה

```
mbox ─► reader ─► parser ─► filters ─► cleaner ─► node_builder ─► Chroma
                                                                    │
שאלה ─► pipeline: ניסוח מחדש לפי השיחה + כתיב שמות (לאה / Leah) + נושא + איש קשר
       ─► retriever: חיפוש לשאלה ולנושא, סינון, עדיפות לאיש הקשר, העדפה לחדש, איחוד לפי מייל
       ─► סינון מיילים חשודים ─► תיוג תאריכים (עבר / עתידי, תאריך עברי, מרחק מהיום)
       ─► LLM: תשובה עם [n] (או בחירת הודעה, ל"תמצא") ─► ממשק: תשובה + רק המקורות שצוטטו
```

| קובץ | תפקיד |
|---|---|
| `readers/mbox_reader.py` | קורא הודעות גולמיות. השכבה היחידה שיודעת שהמקור הוא mbox |
| `email_parser.py` | כותרות, קידודי עברית (windows-1255, RFC2047/2231, 8bit), HTML, קבצים מצורפים, הסרת תוכן מוסתר |
| `pipeline.py` | הכנת השאלה לחיפוש, משותפת לממשק, להערכה ולמלכודות: ניסוח מחדש, כתיב שמות, נושא, איש קשר, "רק מה ש-X כתב" |
| `body_cleaner.py` | הסרת ציטוטים (Gmail, Outlook, מובייל, עברית ואנגלית) וחתימות. העברה מפורקת להודעות לפי סדר, עם תווית כותב לכל אחת. בתשובה בין השורות נשמרת שורה מקוצרת של מה שנענה |
| `attachments.py` | טקסט מ-PDF, docx ומיילים מצורפים. לשאר הסוגים: שם הקובץ והקשר המייל |
| `mail_filters.py` | ספאם, אשפה, Promotions, טווח של 3 שנים, ורשימה שחורה (בנקים, קודי אימות). הרשימה ניתנת לעריכה בממשק |
| `node_builder.py` | Node לכל הודעה ולכל קובץ מצורף. כותרת קצרה ("נושא \| מאת \| תאריך") בטקסט, וה-metadata לא נכנס ל-embedding. קטע מאמצע הודעה מועברת מקבל את תווית הכותב שלה |
| `contacts.py` | טבלת אנשי קשר. ה-LLM מוסיף שם עברי, תעתיק ושמות חיבה (מירי, Miriam). שם שמתאים לכמה אנשים: המשתמש בוחר |
| `indexer.py` | עדכון אינקרמנטלי לפי Message-ID. מייל שנכנס לרשימה השחורה מוסר מהאינדקס |
| `retriever.py` | חיפוש וקטורי עם סינון (כתובת, תאריך, סוג), העדפה קלה למיילים חדשים, ואיחוד החלקים של כל מייל למקור אחד |
| `qa.py` | הפרומפט, ניסוח מחדש של שאלה, זיהוי בקשת "תמצא", חילוץ המקורות שצוטטו, סינון מיילים חשודים, וניסיון חוזר כשהשרת עמוס |
| `date_tags.py`, `hebrew_date.py` | מתייגים כל תאריך במקורות: "(עבר, ט׳ בחשון תשפ״ז, לפני כ-3 שבועות)". מודל שפה טועה בהשוואת תאריכים ובהמרה לתאריך עברי, וקוד לא טועה |
| `app.py` | ממשק שיחה ב-Streamlit (RTL): זיכרון לשאלות המשך, תשובה מוזרמת, שאלות פתיחה והמשך, משוב 👍/👎 |

## בחירות טכנולוגיות

- **LlamaIndex**, כדרישת הקורס, עם **Chroma** מקומי. האינדקס נשמר על המחשב, ותיקיית `storage/` לא נכנסת ל-git.
- **ספק לכל תיבה** (`provider` ב-`mailbox.json`):
  - **הדמו: Gemini החינמי** (`gemini-embedding-001`, `gemini-3.5-flash-lite`). הבודק צריך רק מפתח חינמי. ה-embeddings חזקים בעברית.
  - **תיבה אמיתית: OpenAI** (`text-embedding-3-large`, `gpt-5.4-mini` עם חשיבה בינונית). ב-Gemini החינמי התוכן עשוי לשמש לאימון ולהיקרא בידי בודקים. ב-API של OpenAI הוא לא משמש לאימון. גם המודל חזק יותר בניסוח, בעלות של סנטים.
  - **החלפת ספק לתיבה קיימת:** `indexer.py --provider ... --rebuild`, כי embeddings של ספקים שונים לא ניתנים להשוואה. לכל ספק אוסף Chroma משלו.
- **Node לכל הודעה** ולא לכל שרשור. את ההחלטה בדקנו בהערכה למטה.
- **אין למערכת שום יכולת פעולה:** לא שליחה, לא מחיקה, לא קישורים מתוך מיילים. זו ההגנה העיקרית מפני prompt injection. מעליה יש עוד שלוש שכבות:
  - תוכן מוסתר ב-HTML מוסר כבר בפענוח.
  - מייל שפונה למערכת ה-AI לא נשלח ל-LLM.
  - הפרומפט מורה להתעלם מהוראות שמופיעות בתוך מיילים.

## הערכה

הקובץ `eval/questions.json` מכיל 20 שאלות: 18 עם תשובה, אחת בלי תשובה ואחת שמנסה להפעיל מייל זדוני. בין השאלות יש שאלת סכימה, מיילים שהועברו, ושאלות בעברית על מיילים באנגלית.
הסקריפט `eval/evaluate.py` משווה בין שתי אסטרטגיות chunking: **הודעה בודדת** מול **שרשור שלם**. "המערכת המלאה" מריצה את מה שהממשק מריץ: כתיב שמות, חיפוש לפי הנושא, עדיפות לאיש קשר, העדפה לחדש ואיחוד.

| אסטרטגיה | Gemini (הדמו) | OpenAI 3-small | OpenAI 3-large (התיבה האמיתית) |
|---|---|---|---|
| message (השרשור הנכון נשלף) | **1.00** / 0.90 | 0.71 / 0.58 | 0.89 / 0.69 |
| thread (השרשור הנכון נשלף) | **1.00** / 0.88 | 0.59 / 0.53 | 0.94 / 0.70 |
| message (ההודעה המדויקת נשלפה) | **1.00** / 0.83 | 0.53 / 0.43 | 0.89 / 0.58 |
| המערכת המלאה (הודעה מדויקת) | **1.00** / 0.67 | 0.65 / 0.45 | 0.94 / 0.59 |

(Hit rate / MRR, top-8. ב-OpenAI 3-small נמדדו 17 השאלות הראשונות.) הטבלה המלאה של Gemini, שאלה אחר שאלה, נמצאת ב-[eval/results.md](eval/results.md).

**מסקנות:**
- **Gemini מוצא את כל 18 ההודעות.** `text-embedding-3-small` של OpenAI חלש בעברית, ובעיקר בעברית מול מיילים באנגלית. לכן התיבה האמיתית (OpenAI, בגלל פרטיות) עברה ל-`3-large`.
- **שתי אסטרטגיות ה-chunking מוצאות את השרשור הנכון.** ההבדל בדירוג קטן (MRR של 0.90 מול 0.88).
- **message עדיפה מסיבה מעשית.** היא מאפשרת להפנות להודעה המדויקת ולהציג את התאריך שלה. בשרשור שלם אי אפשר לדעת איזו הודעה בתוכו עדכנית יותר.
- **ב"מערכת המלאה" ה-MRR נמוך יותר, וזה בכוונה.** החיפוש לפי הנושא ולפי איש הקשר מוסיף מועמדים, ומקומות שמורים לחיפוש לפי הנושא דוחקים את ההודעה הנכונה למקום נמוך יותר בתוך ה-8. מה שקובע הוא שהיא בתוך ה-8 (hit rate 1.00), כי ה-LLM מקבל את כולם ממוינים לפי תאריך. בתמורה, שאלות כמו "מירי הודיעה משהו על ההשתלמות?" ו"יש הזדמנות לפגוש את לאה?" מוצאות את המייל גם כשהשאלה ארוכה או כשהשם בשפה אחרת.
- **ההודעה המדויקת לא תמיד במקום הראשון.** בשאלות על מידע שהתעדכן, ההודעה המקורית מדורגת לפני העדכון: הצימר במקום 3, מסיבת החומש במקום 2. לכן המקורות נשלחים ל-LLM ממוינים לפי תאריך, עם הוראה להעדיף את המידע העדכני. בכל השאלות האלה התשובה הסופית נכונה.
- **thread עדיפה רק בשאלה בעברית על מייל באנגלית** (מקום 2 מול 4), כנראה כי השרשור כולל גם את התגובה בעברית.

מעבר להערכה הזו יש 27 שאלות מלכודת שבודקות גם את התשובה עצמה: prompt injection, הנחה שגויה, מידע מחוץ לטווח, ייחוס בשרשור מועבר ושמות חיבה (`tests/check_traps_live.py`). התוצאות: 25/27 ב-Gemini ו-25/27 ב-OpenAI. בשני הספקים, "למה ציפי ביטלה את חוג הציור?" נכשלת רק בניקוד: התשובה מתקנת נכון את ההנחה השגויה ("ציפי לא ביטלה... מיכלי רשומה לחוג"), אבל לא מציינת מקור. ב-Gemini, "מירי הודיעה משהו על ההשתלמות?" שולפת את המייל הנכון, אבל `flash-lite` עונה "לא מצאתי". ב-OpenAI, השאלה על העגלה לא מוצאת את המייל. הסבב הראשון מצא 6 תקלות (בעיה 15 ביומן), והבאים מצאו את בעיות 22-25.

## בעיות שנתקלנו בהן

היומן המלא, עם 25 בעיות, נמצא ב-[problems_log.md](problems_log.md). העיקריות:

1. **קידודי עברית** (בעיות 2 ו-7):
   - windows-1255 לא יכול לקודד סימני כיווניות.
   - `iso-8859-8-i` וכותרות ב-8bit גולמי יצאו כ-����.
   - **הפתרון:** מנסים קודם UTF-8, אחר כך את ה-charset שהוכרז, ואחר כך cp1255, עם טבלת כינויים ל-charset.
2. **ציטוט מול העברה ב-Outlook** (בעיה 4): בשניהם מופיעה אותה כותרת "מאת: / נשלח:". מחיקת ציטוט הייתה מוחקת את התוכן של מייל שהועבר.
   **הפתרון:** הנושא (FW, הועבר) קובע אם זו העברה.
3. **תוכן מוסתר ב-HTML** (בעיה 6): ניסיון prompt injection ב-`display:none`.
   **הפתרון:** אלמנטים מוסתרים מוסרים בפענוח. הספירה היא רק של תגיות מאותו סוג, אחרת תגיות `<p>` לא סגורות "בלעו" את כל המייל.
4. **נטפרי** (בעיות 10 ו-13): Python 3.13 דוחה את תעודת האבטחה של נטפרי.
   **הפתרון:** venv על Python 3.12, בלי לעקוף את הסינון. בנוסף, המסלול החינמי מוגבל ל-100 embeddings בדקה, והאינדוקס ממתין ומנסה שוב.
5. **יותר מדי מקורות** (בעיות 14 ו-15): כל 8 התוצאות הוצגו, אותו מייל הופיע פעמיים, והעדפת מיילים חדשים גברה על הרלוונטיות.
   **הפתרון:** מוצגים רק המקורות שהתשובה ציטטה. כל מייל הוא מקור אחד, בלי לאבד את הקבצים המצורפים שלו. משקל ההעדפה לחדש ירד מ-0.05 ל-0.01.
6. **מי אמר מה** (בעיה 22): התשובה של חני לשמעון יוחסה לשמעון, ובשרשור מועבר "מי הציע" יוחס לכותב הלא נכון.
   **הפתרון:** הכותב רשום בראש כל מקור. כל הודעה מועברת מקבלת תווית כותב, לפי סדר כרונולוגי, וכך גם קטע שנחתך מאמצעה. הודעות מאותו שרשור באות ברצף. "משמעון" מסנן רק את מה ששמעון כתב. ב-OpenAI הופעלה חשיבה (medium).

7. **שם בעברית, מיילים באנגלית, ונושא שטובע בשאלה** (בעיות 23-24): "יש הזדמנות לפגוש את לאה?" לא מצאה אף מייל של Leah Weiss. "מירי מהמשרד הודיעה משהו חדש על ההשתלמות?" דירגה את מייל ההשתלמות במקום 31.
   **הפתרון:** הניסוח מחדש מוסיף כתיב בשפה השנייה ושמות חיבה (לאה / Leah, מירי / מרים), ושורת נושא שמחפשים גם אותה לבד. איש קשר שהוזכר מקבל עדיפות בלי לסנן את השאר. במקביל התברר ש-`text-embedding-3-small` חלש בעברית (0.71), ועברנו ל-`3-large` (0.94).
8. **תאריכים** (בעיות 18 ו-25): המודל כתב "האירוע העתידי" על חתונה שכבר הייתה, והמיר את אותו תאריך לתאריך עברי שונה בכל פעם.
   **הפתרון:** הקוד מתייג כל תאריך במקורות: "(עבר, ט׳ בחשון תשפ״ז, לפני כ-3 שבועות)". הלוח העברי מחושב באלגוריתם הסטנדרטי, בלי תלות חיצונית. המודל רק מעתיק.

## מגבלות ושלבים הבאים

- **שאלות סכימה** ("כמה הוצאתי"): החיפוש מחזיר רק את 8 המיילים הרלוונטיים ביותר, והממשק מזהיר שהתשובה עלולה להיות חלקית. הפתרון המתוכנן הוא מצב "רשימה מלאה" לפי metadata.
- **תמונות ו-PDF סרוק:** כרגע נשמרים רק שם הקובץ והקשר המייל. מודל ראייה מתוכנן לשלב 2.
- **איכות המודל:** `gemini-3.5-flash-lite` לפעמים לא יציב בניסוח ובייחוס. `gemini-3.5-flash` טוב יותר, אבל במסלול החינמי מוגבל ל-20 קריאות ביום. במסלול בתשלום, המעבר הוא שורה אחת ב-`config.py`.
- **מכסות המסלול החינמי:** 15 קריאות LLM בדקה, וכל שאלה היא 2 קריאות (ניסוח מחדש ותשובה). בשימוש רגיל זה מספיק. סקריפטי ההערכה והמלכודות ממתינים כשהמכסה נגמרת.
- **זיכרון השיחה** מוגבל ל-3 התורות האחרונות.
- **"איפה השאירו את העגלה?"** ב-Gemini המייל באנגלית נמצא, אבל רק במקום 7. ב-OpenAI `3-large` הוא לא נמצא בכלל: החיפוש לפי משמעות לא מקשר "השאירו" ל-"left with your neighbor".
- **עוד לא נבנה:** קורא Gmail API (`gmail.readonly`).
